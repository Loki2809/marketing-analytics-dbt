Target roles: Analytics Engineer / Data Engineer (US).

## Business story
A fictional online store runs ads on Google, Meta, and email.
Marketing leadership asks: Which channels bring customers? What does each customer cost (CAC)?
What return do we get on ad spend (ROAS)? Where do people drop out of the funnel?

## Stack
- Warehouse: Snowflake (30-day free trial). Use an X-SMALL warehouse with auto-suspend at 60 seconds to save credits.
- Transformation: dbt Core (`dbt-snowflake`), run locally.
- Data generation: Python (pandas + Faker) creates realistic synthetic CSVs.
- Version control: GitHub (public repo).
- CI: GitHub Actions runs `dbt build` on every pull request.
- Dashboard (final step): Power BI connected to Snowflake marts.

## Raw data (generated by Python, loaded into Snowflake schema RAW)
- `customers`: customer_id, email, signup_date, country, updated_at
- `web_sessions`: session_id, customer_id (nullable), session_start, utm_source, utm_medium, utm_campaign, device
- `events`: event_id, session_id, event_name (page_view, add_to_cart, begin_checkout, purchase), event_timestamp
- `orders`: order_id, customer_id, order_date, revenue, status
- `ad_spend`: date, channel, campaign, impressions, clicks, spend
- `campaigns`: campaign_id, campaign_name, channel, start_date, end_date

Include messy data on purpose (duplicates, null UTMs, mixed-case channel names, test orders)
so the staging layer has real cleaning work.

## dbt layers
- `staging/` — one model per raw table. Rename, cast types, clean. No joins. Prefix `stg_`.
- `intermediate/` — joins and business logic (sessionized funnel, touchpoints per customer). Prefix `int_`.
- `marts/` — final tables for reporting:
  - `dim_customers`, `dim_campaigns`, `dim_date`
  - `fct_sessions`, `fct_orders`, `fct_ad_spend_daily`
  - `fct_attribution` (first-touch and last-touch)
  - `mart_marketing_kpis` (CAC, ROAS, conversion rate by channel and month)

M1 done (branch `m1/data-generator`).
- `python data_generator/generate_data.py` builds clean tables, then adds deliberate mess (separate MESS_SEED)
  and writes 6 CSVs to `data/raw/`. Window = last 365 days up to today, so counts shift slightly each day.
- `python data_generator/load_to_snowflake.py` loads them into MARKETING_DB.RAW: all columns VARCHAR plus
  `_LOADED_AT` (for freshness); PUT + COPY INTO via stage CSV_STAGE and file format CSV_FORMAT; tables are
  replaced on every run.
- Orders have no session_id: attribution must match customer_id + time. Only logged-in visits can purchase.

M2 done (branch `m2/staging`). `dbt build` = 6 views + 49 tests, all pass.
- `models/staging/_sources.yml`: source `raw` (MARKETING_DB.RAW), freshness on `_LOADED_AT` (warn 3 days, error 7).
- `models/staging/_stg_models.yml`: descriptions + tests. Generic test args go under `arguments:` (dbt 1.10+ style).
- Staging models are views (set in dbt_project.yml). Standard channel names everywhere: google / meta / email,
  plus `direct` in stg_web_sessions (no UTM; includes ~1,300 ad visits that lost their tags).
- Dedup pattern: `qualify row_number() over (partition by <id> order by ...) = 1` (customers keep latest updated_at).
- Test data is flagged, not deleted: stg_customers.is_test_account (@test.com), stg_orders.is_test_order
  (status 'test'). Marts must exclude both (orders of test accounts need a join to stg_customers).
- stg_orders splits raw order_date into ordered_at (timestamp, for attribution) and order_date (date).
- Channel mapping is repeated in 3 models on purpose; refactor into a macro in M4.

M3 done (branch `m3/marts`). Intermediate = views, marts = tables (dbt_project.yml).
- int_sessions_funnel: 1 row per visit; events summarised (count_if) then left-joined; funnel_stage 1-4.
- int_customer_touchpoints: logged-in visits numbered per customer (touchpoint_number, is_first_touch).
- dim_date (generator() date spine from earliest fact date to current_date), dim_customers (test accounts
  removed; first-touch channel; completed orders/revenue), dim_campaigns (+ spend totals).
- fct_sessions (+ campaign_id), fct_orders (both kinds of test orders removed; completed_revenue;
  completed_order_number = 1 marks a new paying customer, for CAC), fct_ad_spend_daily (+ CTR, CPC).
- fct_attribution: 1 row per order; time-based join (same customer AND session_start <= ordered_at);
  first touch = touchpoint 1, last touch = latest visit before the order.
- Pattern: always summarise (group by) before joining to avoid fan-out; unique tests on every PK prove it.
- Reconciliation checks that tie out: purchases in fct_sessions = rows in fct_orders; completed revenue in
  fct_orders = lifetime_revenue in dim_customers; spend identical across stg/dim/fct.
- Story: first touch credits google/meta (finding customers); last touch credits email (closing sales).

M4 done (branch `m4/advanced`).
- Macro `macros/clean_channel.sql` (+ `_macros.yml`): one CASE mapping any channel spelling to google/meta/email
